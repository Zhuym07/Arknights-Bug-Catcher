# 源石防线

可离线运行的单机触摸小游戏，纯静态 HTML / CSS / Canvas / ES modules，无后端、运行时 CDN 或构建依赖。

## 预览

```powershell
python -m http.server 4180 --bind 127.0.0.1 --directory public
```

打开 http://127.0.0.1:4180/ 。第一次打开需要联网，页脚显示「离线可用」后即可断网重开。离线缓存、安装需要 localhost 或 HTTPS；不能直接双击 HTML。安装入口由浏览器菜单提供，移动端支持添加到主屏幕。

## 玩法

点击开始后有 3 秒准备，随后挑战 25 秒。上方两个红门、左下红门、右侧红门各自持续出怪，开局保证四门各出现一只。点按命中消除并加 1 分；到达中央蓝门计为漏网。高台不可通过，原石虫沿格子选择不同合法路线。支持多个手指同时点按；切后台自动暂停，回来点击「继续行动」。结算可立即重开；不需要账号，也不上传成绩。

场景按录像的实际游戏区域采用 8:5 比例，保留完整地图。外层自适应 4:3、16:9 显示器和手机。手机横屏体验更好，右上角可进入全屏。

难度随时间递增：0–8 秒接敌、8–17 秒加压、最后 8 秒突袭。基础速度从每秒约 190–225 场景像素提升至末段约 303–338 像素；常规出怪间隔依次为 0.42、0.32、0.24 秒，末段周期性双门同时出怪。开局四门在 0.66 秒内各出一只，一局约 90 只。点按范围仍保留至少 44 CSS 像素直径。

状态栏独立于地图，采用参考录像的浅色金属面板与金色边框。结算时只保留计时，分数和漏网数集中在大面板，避免重复计数，主分数在大屏使用 176px 字号，便于志愿者读分。网页固定在视口内，禁止页面滚动、触摸拖移和图片拖拽。门的顶面与底面复用地砖投影，竖边保持竖直，远近尺寸随所在行变化。工具图标来自 Lucide，许可见 public/assets/lucide-LICENSE.txt。

场景提供一个 WebGL 复古画面开关：场景 Canvas 会以较低分辨率采样，再叠加有限色阶、抖动、轻微色散、扫描线、暗角和颗粒，模拟低多边形 3D 游戏的屏幕质感。交互坐标仍以原始 Canvas 为准，HUD、按钮和结算分数保持 DOM 绘制，着色器不可用时会自动退回原始画面。

## Cloudflare Pages 部署

发布目录是 **public**。Dashboard 的 Pages 静态站点设置中，框架选择 None，不需要构建命令，输出目录填写 `public`。也可以使用 Direct Upload 上传 public 内全部文件。不要上传 art、scripts、tests。

`public` 已是完整发布产物，无需安装 npm 包。`_headers` 给服务工作线程设置重新验证策略。更新发布时同时增加 `public/service-worker.js` 的 CACHE_NAME 版本，以便安装新离线资源。

## 地图和素材

- `public/level.mjs` 是唯一地图数据源：9 列 5 行，四门、中心、11 个高台以及透视投影。改布局后执行 `node scripts/build-map.mjs`，同步生成地图，避免可见高台和寻路不一致。
- 布局参考用户提供的游戏录像；另一张完整地图截图仅用作门与工业地图风格参考，未用作底图。没有从录像裁切背景。
- `public/assets/map-layout.svg` 为重绘背景：新生成的 Image2 机械舱提供机柜、马达、管线、护栏和地面材质；SVG 按地图数据绘制准确的地砖、高台与四红一蓝的门。移除了顶部 L 形管、左侧线框板和右侧紫色徽章三处额外装饰。位图以内嵌数据保存，确保 Canvas 和离线模式均能显示完整背景。
- 新背景原图在 `art/image2-chamber.png`，提示词在 `art/image2-chamber-prompt.txt`；`art/chamber-background.webp` 是对齐墙面高度并压缩后的制作素材。执行 `node scripts/build-map.mjs` 将它内嵌进发布地图。`scripts/stylize-map.py` 记录生成和对齐过程，依赖本机 gpt-image-2 技能、凭据和 Pillow；运行游戏无需这些。旧研究图保留在 `art/image2-map-study.png`。
- 两种原石虫来自用户提供的图片，只去除周围背景并裁去透明边缘，保留原来的外观；原图存于 `art/references`。当前移动是独立精灵的位移、翻转与轻微起伏，没有原版逐帧动画或音频。
- `art/qa` 是浏览器验证截图，不参与发布。

## 检查

```powershell
node --test tests/game.test.mjs
```

覆盖所有门连通、随机路径不穿高台、路线差异、准备与计时、四门出怪、命中/漏点/重复点击、漏怪、结算、重开、暂停、低帧率计时。

浏览器测试需安装 `playwright-core`，系统安装 Chrome，并启动上述 4180 端口预览服务：

```powershell
node tests/browser.cjs
```

在此环境通过 NODE_PATH 使用预装的 playwright-core，没有给游戏添加运行时依赖。浏览器测试覆盖开始、命中、暂停、漏怪、结算、重开、离线 reload 后继续游玩；另检查 1920×1080、390×844、844×390 的布局、多点触摸、结算大分数，以及触摸滑动、滚轮和方向键不会带动网页。实际大屏的可用触点数量取决于现场硬件和浏览器，需现场校准。
